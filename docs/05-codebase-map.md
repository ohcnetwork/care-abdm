# 05 — Codebase map (as of 2026-09-21, ADR-011 with its amendments, ADR-013 to ADR-018)

Read this before touching code. Every module has one job; keep it that way.

## Backend — `backend/src/abdm/` (Django app, label `abdm`, mounted at `/api/abdm/`)

| Module | Job | Invariant |
|---|---|---|
| `apps.py` | `AppConfig`; `ready()` imports `care_seams` and `signals` | Only place side-effect imports happen |
| `settings.py` | Reads `ABDM_*` env into `plugin_settings` (pattern from `care_token_display`); a bool default (`DEVELOPER_MODE`) reads `1/true/yes/on` | Names carry no environment marker; sandbox and production differ by value only |
| `care_seams.py` | Registers with Care: `Patient.extensions["abdm"]`, `Facility.extensions["abdm"]` (typed: `hip_name`, `counters`; link-written (ADR-016): `facility_id`, `facility_name`, `hfr` the registry record snapshot; the resumable `hfr_onboarding`; server-written `hip_id`, `hrp_registered_at`, `last_error`), and the 2 `auto_maintained` identifier configs (`abdm/abha-number`, `abdm/abha-address`) | Extension fields carry `x-ui.render_blacklist`; host forms never render them |
| `models.py` | M1: `AbhaTransaction`, `AbdmProfileShare`. Audit: `AbdmOutboundRequest` (with `request_headers`: names → lengths, ADR-018), `AbdmCallback` (with `processing_error`, the traceback of a handler that raised, and `processed_at`). M2: `AbdmLinkToken`, `AbdmCareContext` (`hi_types` derived from the linked items), `AbdmShareItem` (ADR-013: 1 row per shareable record, `staged → queued → linked`, or `failed` / `excluded`), `AbdmLinkSession`, `AbdmConsent`, `AbdmDataRequest`. M4 (ADR-015): `AbdmHprProfile` (user ↔ HPR ID, the person's HPR token), `AbdmHprLogin` (an OTP login in progress), `AbdmHpidTransaction` (the HPID creation wizard; the Aadhaar photo until creation). Ciphertext is never stored |
| `migrations/` | `0001_initial` (rebased with Care develop 2026-09-17), `0002_abdmshareitem` (adds the table and turns every advertised `hi_types` value into a linked item), `0003_hiu_consent_requests` (the 4 M3 tables), `0004_nhpr_hpr_hfr` (the 3 M4 tables; `AbdmHfrOnboarding` was removed by ADR-016 before any deployment), `0005_developer_mode` (the 3 audit columns of ADR-018) | Must match `models.py` |
| `signals.py` | `post_save(Patient)`: consume `extensions.abdm.txn_id` → identifiers (M1). | `tasks.py` | `dispatch_callback` (verified callback → handler; the M3 handlers are in the same table; a handler that raises leaves `processing_error` = the traceback, and `processed_at`; every run sets the worker heartbeat `abdm:worker:last_seen`, which the readiness check reads); `stage_record` (stage 1 record); `sync_encounter` (Encounter change; close → link); `link_care_context` (1 link call for the queued items); `notify_care_context` (delayed notify, F9); `retry_share_items` (periodic, every 5 min: re-queue due items, ADR-013 D4); `hiu_housekeeping` (periodic, every 15 min: fail a health-information request with no push inside its window and tell the gateway; erase bundles past `erase_at`, ADR-014) | A Celery worker must run for M2, M3 and Scan and Share. | `urls.py` | Route table. One catch-all POST route (last) receives every gateway callback: the bridge URL is `<base>/api/abdm`, so a callback lands at `/api/abdm/<callback path>` whatever the path. Mirrors: `frontend/src/lib/careApi.ts`, `bruno/` | Change all 3 together |
| `gateway/session.py` | Gateway session token, Redis-cached, 60 s margin; the session call is recorded (`gateway-sessions-create`) with `clientId`, `clientSecret` and both tokens redacted | The token never leaves the server |
| `gateway/outbound.py` | `send()`: every call to ABDM or to an HIU push URL; adds `REQUEST-ID`, `TIMESTAMP`, `X-CM-ID`, `Authorization`, and the facility's gateway service id as `X-HIP-ID` (`role="hip"`, default) or `X-HIU-ID` (`role="hiu"`, M3), or no facility header at all (`role="none"`, the NHPR calls); records `AbdmOutboundRequest` with `request_headers` as names → lengths; reads all 3 error envelopes; `failure(row)` gives the `errors.Failure`; keeps the response headers of a refusal in `response_headers`. `record()` (ADR-018): the same row for a call another transport made (`abha/client`, the session, the JWKS), body and answer through `dev.redact.redact()` **before the save**; never raises | A 2xx with an `{"error": {...}}` body is a failure. `send()` never raises: a transport failure is recorded and returned, so every caller reads 1 shape. ABDM answers some refusals with an empty body, so the headers are the only evidence (E11) |
| `gateway/certs.py` | Gateway JWKS, cached 6 h, fetched with the gateway bearer token (the sandbox answers 401 without it); recorded as `gateway-get-gateway-certs` | Raises `GatewayCertsError`; the receiver turns it into a 503 |
| `gateway/bridge.py` | Callback URL derivation, `PATCH bridge/url`, live `GET bridge-services` (caches the bridge id 1 h), HRP service registration on `ABDM_HSP_URL` with 1 entry per link type, `HIP` and `HIU` (ADR-015; body from `nhpr/rules.hrp_linkage_body`) | The gateway is the source of truth for bridge state; nothing is snapshotted |
| `gateway/views.py` | `GET gateway/status`, `GET bridge` (staff), `POST bridge/register-url` and `GET admin/overview` (superuser: gateway status, live bridge and services, every facility with its ABDM state through `facility/create.list_facilities`) | Probes never return tokens |
| `callbacks/paths.py` | Pure: callback path → operation id. The real paths carry an `/api` prefix the docs omit (observed 2026-09-17: `{bridgeUrl}/api/v3/hip/token/on-generate-token`); `operation_for_path()` drops it, and the `/v0.5/...` spellings are aliases. | `callbacks/receiver.py` | Stores each callback before verification; idempotency key; resolves the operation id through `paths.py` | Never dispatch an unverified callback |
| `callbacks/signature.py` | JWT against the gateway JWKS: configured header first, then any JWT-shaped header; algorithm from the matching JWK (RS256 or RS512); returns the header name; `seconds_late()` reports how late the token was | Fails closed in every environment, but accepts a token that expired inside `ABDM_CALLBACK_SIGNATURE_LEEWAY_SECONDS` (default 3600). The gateway repeats a refused delivery about 16 minutes later with the same, dead token (finding E10) |
| `callbacks/views.py` | Generic callback view (`AllowAny`): store, verify, `202 {}`; 401 on a bad signature, 503 when the verifier cannot run; never raises (Care's `ATOMIC_REQUESTS` would roll the row back). Folders: `auth`, `probes`, `bridge`, `facility`, `abha-enrol`, `abha-login`, `transactions`, `patient`, `encounters`, `hiu`, `nhpr`, `add-facility`, `callbacks`, `scan-share`, `dev`. 90 requests; every route in `urls.py` has one. Secrets and personal data are secret variables.

## Data flow — HIP-initiated link (M2 journey 1)

1. Encounter saved → `signals.sync_encounter_care_context` → `tasks.sync_encounter` after commit.
2. `hip.contexts.sync_encounter`: facility set up? patient has ABHA? `available_hi_types` non-empty? → `AbdmCareContext` row.
3. No usable link token → `m2-generate-link-token` (202); the token lands on `/v3/hip/token/on-generate-token` → `AbdmLinkToken.active` → `link_pending_contexts`.
4. `m2-hip-link-care-context` with `X-Link-Token` (202) → `link_requested`.
5. `/v3/link/on_carecontext` → `linked` (or `failed` with the gateway code) → `m2-link-care-context-notify` → `/v3/links/context/on-notify` → `notified_at`.

## Data flow — consent and transfer (M2 journey 4)

1. `/v0.5/consents/hip/notify` (or `/api/v3/consent/request/hip/notify`) → `AbdmConsent` → `m2-consent-hip-on-notify` ack.
2. `/v0.5/health-information/hip/request` → `AbdmDataRequest` (deadline = received + 20 min) → validate → `m2-hip-health-information-on-request` ACKNOWLEDGED or ERRORED.
3. `transfer()`: for each linked care context of the consent in the requested range × each consented HI type with data → `build_bundle` → MD5 → encrypt → 1 push to `dataPushUrl` → `m2-hip-data-flow-notify` TRANSFERRED or FAILED.

## Data flow — HIU consent and fetch (M3, ADR-014)

1. Desk `POST patients/<id>/abha/consent-requests` → `AbdmConsentRequest` → `m3-consent-request-init` (202, `X-HIU-ID`).
2. `/v3/hiu/consent/request/on-init` → `consent_request_id`. The desk may `refresh` → `m3-consent-request-status` → `/v3/hiu/consent/request/on-status`.
3. `/v3/hiu/consent/request/notify` GRANTED → `AbdmConsentArtefact` rows → `m3-consent-notify-ack` → `m3-consent-fetch` per artefact → `/v3/hiu/consent/on-fetch` → detail stored.
4. A live artefact → `AbdmFetchRequest` (new X25519 key pair, our nonce, `dataPushUrl`, 20-minute deadline) → `m3-health-information-request` → `/v3/hiu/health-information/on-request` → `transaction_id`.
5. The HIP posts to `/api/abdm/v3/hiu/health-information/transfer` (signed catch-all) → `handle_transfer`: decrypt, MD5, `AbdmFetchedRecord` per entry → after the last page `m3-health-information-notify` RECEIVED / FAILED; key blanked; ciphertext scrubbed.
6. DENIED / EXPIRED / REVOKED (notify or on-status) → artefacts settled, records erased. `hiu_housekeeping` erases bundles at `erase_at` and fails a request with no push inside its window.
